# All Tasks

`docs/backlog.md` の未完了タスク（`- [ ]`）を上から順に**全部**実装してください。
1タスクだけの `/next-task` と違い、最後まで走り切るのが目的。

## 現在のバックログ

!`cat docs/backlog.md`

## 手順

各タスクごとに以下のループを回す。

1. **対象タスクを選ぶ**
   - `docs/backlog.md` のファイル先頭から最初の `- [ ]` を選ぶ
   - 選んだタスクと、その下のインデント行（メモ・受け入れ条件）を読む

2. **スキップ判定**
   - 以下に該当するタスクは**実装せずスキップ**（バックログには残す）：
     - ユーザーの判断・採用決定が必要なもの（例: 「A/B/C のどれを採用するか決める」「設計案を比較して選ぶ」）
     - 仕様が曖昧で実装方針が一意に決まらないもの
   - スキップしたタスクは記録しておき、最後の報告でまとめて提示する

3. **実装**（スキップしなかった場合）
   - メモに書かれた対象ファイル・受け入れ条件に従う
   - AGENTS.md のルール（TypeScript strict、Tailwind のみ、データ取得は src/lib/ 集約等）を遵守
   - 必要なら関連 docs（@docs/UI.md, @docs/DATA.md, @docs/VOTING.md）を on-demand で参照
   - 既存パターンの流用を最優先（新規抽象化を勝手に作らない）
   - 1タスクが大規模化しすぎたら、その時点で一旦停止してユーザーに相談

4. **動作確認**
   - UI 変更は HTML スナップショットまたはブラウザで簡易確認
   - 全タスク終わってから dev server を回すのではなく、影響範囲が大きいものはその場で見る

5. **バックログ更新**
   - 完了タスクは `docs/backlog.md` から該当行（タイトル + ぶら下がりメモ）を**削除**
   - **セクション見出し（`## モック / UI` 等）は残す**
   - 削除内容を `docs/done.md` 冒頭の `<!-- 完了タスクをここから追記していく -->` 直下に追記
     - 当日の日付見出し（`## YYYY-MM-DD`）がなければ作る
     - 元タイトル + 1〜2行の成果メモ（実装ファイル、判断ポイント）
   - 派生タスクが見つかったら `docs/backlog.md` の適切なセクション末尾に `- [ ]` で追記
     - **派生タスクはこの実行では拾わない**（次回以降）

6. **次のタスクへ**
   - バックログを再読込して、まだ未スキップの `- [ ]` があれば 1 に戻る
   - 全部完了 or 全部スキップになったら終了

## 終了時の報告

以下をまとめて報告：

- **実装したタスク一覧**（順番に、各タスクの主要変更ファイル付き）
- **スキップしたタスク**とその理由（ユーザー判断待ち等）
- **追加した派生タスク**があれば一覧
- **git commit はしない**（ユーザーが内容を確認してからまとめて扱う）

## 注意

- git commit / push は**絶対にしない**
- 1タスクの実装で予想外に範囲が広がったら、そこで止めてユーザーに相談
- スキップ判定は安全側に倒す（迷ったらスキップ）
- バックログを大幅に書き換えない（完了削除・派生追記のみ）
- 同じタスクを2回処理しない（無限ループ防止のため、毎ループでバックログを読み直す）
