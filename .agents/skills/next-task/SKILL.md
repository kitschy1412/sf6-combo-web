# Next Task

`docs/backlog.md` の最初の未完了タスク（`- [ ]`）を読んで実装してください。

## 現在のバックログ

!`cat docs/backlog.md`

## 手順

1. **対象タスクを特定**
   - `$ARGUMENTS` が空でなければ、`- [ ]` 行のうち $ARGUMENTS を含むものを優先
   - そうでなければファイル先頭から最初の `- [ ]` を選ぶ
   - 選んだタスクと、その下にぶら下がっているメモ（インデントされた行）を読み込む

2. **実装**
   - メモに書かれた対象ファイル・受け入れ条件に従う
   - AGENTS.md のルール（TypeScript strict、Tailwind のみ、データ取得は src/lib/ 集約等）を守る
   - 必要なら関連 docs（@docs/UI.md, @docs/DATA.md, @docs/VOTING.md）を on-demand で参照
   - 既存パターンの流用を最優先（新規抽象化を勝手に作らない）

3. **動作確認**
   - 開発サーバーが起動していなければ起動して該当ページを確認
   - UI 変更なら必ずブラウザで確認、または HTML スナップショットで検証

4. **バックログ更新**
   - 完了したら `docs/backlog.md` から該当タスク（タイトル行 + ぶら下がりメモ）を **削除** する
   - **セクション見出し（`## モック / UI` 等）は、配下のタスクが全部消えても残す**（受け皿として保持）
   - 削除した内容を `docs/done.md` の冒頭の `<!-- 完了タスクをここから追記していく -->` 直下に追記
     - 日付見出し（`## YYYY-MM-DD`）が当日分なければ作る
     - 元タスクのタイトル + 1〜2行の成果メモ（実装ファイル、判断ポイント）を残す
     - 詳細は git log が正本なので冗長に書かない
   - 実装中に派生タスクが見つかったら、`docs/backlog.md` の適切なセクション末尾に `- [ ]` で追記

5. **報告**
   - どのタスクを実装したか
   - 触ったファイルとその要点
   - 派生タスクを追加した場合はその一覧

## 注意

- バックログを大幅に書き換えない（チェック更新と派生タスク追記のみ）
- 1度の実行で1タスクのみ実装する（連続で複数タスクを処理しない）
- 不明点があれば実装前にユーザーに質問する
