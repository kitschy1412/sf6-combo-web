# Roadmap

このサイトの目的・現状・今後の方針をまとめた長期視点のドキュメント。
細かい実装タスクは [backlog.md](./backlog.md) を参照（`/next-task` はそちらだけを読む）。

---

## 目的

SF6 のコンボを **YouTubeタイムスタンプ付きで整理・共有・投票** できる Wiki 型サイト。

- 個人の練習メモを永続化する（personal）
- 良いコンボは公開して他人と共有する（shared）
- 他人のコンボを自分用に派生させる（fork）
- 「現バージョンで成立しないコンボ」をコミュニティで識別する
- 〆方法ごとに **起き攻め** を自動でサジェストしつつ、ルート個別の手動上書きを許す
  （同じ〆技でも、繋ぎや距離・高さでフレーム状況や使える重ねが変わるため）

データは [`sf6-combo-archiver`](../../sf6-combo-archiver) パイプラインが Supabase に投入する
（同一 Supabase プロジェクトを共有）。本サイトは表示と投票のみを担う。

## これまで

### Phase 0 — 旧版（稼働中）
Astro + Supabase 直結のシンプル版。`sf6-combo-archiver` の出力をそのまま表示する読み取り中心サイト。

- `src/pages/index.astro` — キャラ一覧
- `src/pages/[character].astro` — キャラ別コンボ一覧
- `src/pages/combo/[id].astro` — コンボ詳細 + YouTube 埋め込み + 投票
- `src/pages/api/vote.ts` — 投票 API（Wilson Score、IPハッシュ制限）
- スキーマ: `characters` / `combos` / `votes` のみ

### Phase 1 — Wiki型オーバーホールの UIモック（完了）
`src/pages/mock/` 配下に新UIを Rashid 限定・ハードコードデータで作り込んだ。
バックエンド未接続。論点を「触って詰める」ためのデザインモック。

詰めた論点:
- コマンド入力 A/B/C（チップ式 / フリーテキスト / ハイブリッド）
- コンボ分岐ツリー（共通プレフィックスから複数ルート、葉ごとに独立した damage / 〆分類 / 投票）
- 〆分類による起き攻めの自動紐付け
- personal / shared / forked のバッジと区別
- 重複アップロード検出
- 「現バージョンでは不可」票（Good/Bad とは独立軸）
- 〆分類管理、起き攻め入力、ダウン状況詳細、admin
- コンボ一覧の大分類・小分類フィルタ（`<select>` + AND結合）
- コンボ一覧の分岐ツリー折り畳み（デフォルト折り畳み、▶トグルで展開）
- コンボ一覧の大分類・小分類グループヘッダ表示
- SA / D ゲージ自動計算（`src/lib/gauges.ts` を起き攻めフォームと共有）
- コンボ詳細ページの大分類・小分類バッジ表示
- モックトップへの Phase 2 TODO セクション追加

参考: `src/pages/mock/index.astro` がモック画面の索引。

## これから

各 Phase は前の Phase に依存する。Phase 内のタスクは [backlog.md](./backlog.md) に切り出す。

### Phase 2 — 仕様確定とスキーマ設計（進行中: 仕様詰め）
モックで詰めた論点を「採用 / 不採用 / 保留」で確定し、Supabase スキーマに落とす。
`sf6-combo-archiver` 側にも影響するので、archiver と歩調を合わせる必要がある。

決まったこと（2026-05-23）:
- **オーナーシップ**: `combos` / `okizeme` を同一テーブルで保持し、`owner_id` + `visibility(private/unlisted/public)` + `forked_from` を持つ。
  公開／非公開は visibility の切替で済ませ、fork は同テーブル内の複製で派生関係を保つ。

決まったこと（2026-05-25）:
- **サイトの3軸構成**:
  1. **世界全体（`/explore/[character]`）** — 公開コンボの読み取り専用ビュー。D&D / 追加 / 順序変更は不可。
     ユーザー操作として許すのは「自分用にfork」「投票（Good/Bad/現ver不可）」「絞り込み」のみ。
  2. **自分用（`/character/[name]`）** — 個人のコンボ・起き攻め一覧。D&D での並び替え、追加、編集可。
     ここで作成したコンボを「アップロード」操作で `/explore` に公開する（= visibility を public にする）。
  3. **詳細（`/combo/[id]`）** — コンボ単体の詳細・動画埋め込み・投票。
- **`/explore` の表示順（グローバル設定）**: ユーザー個別の並び替えは持たず、サイト全体で決まる。
  - 外側: **〆分類（大分類 → 小分類）でグルーピング**
  - 内側: ユーザーがビュー切替できる（**投票スコア順 / ダメージ降順 / 新着順**）
- **ノート**（旧称プレイリスト）: コンボノートと起き攻めノートを別系統として持つ。
  1ノートは1種類のアイテムのみを順序付きで束ねる。例: 「中央 SA2〆ノート」「対モダン用ノート」。
  URL は `/me/notes/combos/[id]` / `/me/notes/okizeme/[id]`。
  ※「コンボとその起き攻めをセットで束ねる」用途は、コンボ詳細の〆分類経由で自動紐付け表示されるため、ノート側では持たない。
- **コンボ一覧の起き攻め展開**: `/[character]` のコンボ一覧で、各行に起き攻め展開トグル（▶）を置く。
  クリックでその行の〆分類に紐付く起き攻めをインライン展開する。
- **用語**: 「プレイリスト」は不使用。研究記録の単位として「ノート」を採用。

決めるべきこと:
- 入力UI A/B/C のどれを採用するか（または統合形）
- コンボ分岐ツリーの DB 表現（フラットな combos に parent_id か、JSON で持つか）
- 〆分類のマスタ設計（自由文字列 / マスタテーブル / タグ）
- 「現ver不可」票を votes に持つか別テーブルにするか
- ノートのスキーマ詳細（`notes` + `note_items` の2テーブル想定）

### Phase 3 — モックの本実装移行（Rashid）
モックを Supabase 接続に置き換え、Rashid のみで本番稼働させる。

- `src/pages/mock/` の各画面を `src/pages/` 直下に昇格
- ハードコードデータを `src/lib/` 経由の Supabase クエリに差し替え
- 入力フォームの POST API を実装

### Phase 4 — 認証とオーナーシップ
personal / shared / fork は「誰の」が必要。
Supabase Auth で最小限のユーザ概念を入れる（OAuth 1個でよい）。

- ログイン導線
- personal 投稿の本人限定編集
- fork 時のオーナー切り替え

### Phase 5 — 全キャラ展開
Rashid 専用に作った部分を全キャラ対応に広げる。技名・notation・キャラバッジ色などのキャラ依存値を整理。

- `src/lib/movenames.ts` の全キャラ網羅
- キャラ別の特殊技対応（例: モダン専用入力、特殊ゲージ）
- 旧版 `src/pages/[character].astro` の廃止 or リダイレクト

### Phase 6 以降 — 拡張
優先度は未定。Phase 5 完了後に再評価。

- 検索・フィルタの高度化（タグ、難易度、ダメージレンジ）
- ソーシャル要素（コメント、プレイヤーフォロー）
- パフォーマンス計測と最適化
- archiver の YouTube 自動取り込みとサイト側の表示連携
- 両サイドへのアフィリエイト枠設置（中央コンテンツは 1200px 想定 = 必要ビューポート約 1560px）

### モバイル対応（かなり後回し）
現状の UI は PC ファースト（コンボ一覧が 8カラムテーブル等）でスマホでは破綻する。
ただし当面の優先度は低い：本サイトの読者層は PC でフレームデータや動画を見ながら使う想定が中心。
着手する場合の指針：

- 一覧テーブルはモバイルでカード化（または重要カラムだけ `hidden md:table-cell` で残す）
- コマンドノーテーションは横スクロール許容
- 投票・編集UI のタップ領域確保
- Phase 5（全キャラ展開）完了後、利用ログを見て着手判断
